# Test Design

Timestamp: 2026-06-19 11:19 Europe/London

The test suite uses Vitest plus Foldkit's testing helpers. It is organized around architecture boundaries: reducer stories, mounted scenes, pure domain tests, runtime mocks, schema/invariant tests, and shared service tests.

## Story Tests

`Story.story` drives update functions directly:

```ts
Story.story(
  Counter.update,
  Story.with(Counter.init),
  Story.message(Counter.PressedIncrement({ duration: 0 })),
  Story.model(model => expect(model.count).toBe(1)),
  Story.Command.resolveAll(resolveClick, resolveSpeak),
  Story.Command.expectNone(),
)
```

This style is used heavily in game tests because it verifies state transitions and command contracts without needing the browser.

Good examples:

- `src/games/counter.test.ts`: duplicate mobile pointer events increment exactly once.
- `src/games/findit.test.ts`: wrong guesses reveal hints after three attempts.
- `src/games/bubbles.test.ts`: popping one bubble does not mutate the others.
- `src/main.test.ts`: persisted-message policy emits `PersistSettings` only for settings changes.

## Scene Tests

`Scene.scene` mounts the real view and performs user-like actions:

- Counter renders and clicking `+1` updates visible text.
- Find It renders the prompt and win overlay.
- Bubbles renders empty/all-popped states and color selector UI.
- Landing and audio-test pages have their own scene tests.

Scene tests are best for checking that view wiring actually emits the intended messages.

## Pure Domain Tests

Pure helpers get direct tests:

- `Draw.targetPoolFor`, `Draw.normalizeTopN`, brush-size and ink-color normalization.
- `MusicBox.buildKeyboard`, `transposePitch`, `Pitch.fromString`.
- `Counter.numberToWord`, parser helpers.
- Find It emoji pack normalization and pair generation.

These tests are fast and give precise failure messages.

## Runtime Mock Tests

Web APIs are tested with focused mocks rather than real browser/audio behavior:

- `src/games/musicboxAudioRuntime.test.ts` builds fake `AudioContext` nodes and asserts start/stop/connect behavior.
- `src/audio.test.ts` tests shared audio context behavior.
- `src/speech.test.ts` and parts of `src/main.test.ts` mock Web Speech to assert spoken text, rate, pitch, and language.
- Wake monitor tests inject window/time/reset dependencies.

This preserves confidence in imperative code while keeping tests deterministic.

## Schema and Invariant Tests

`src/invariants.test.ts` is the safety net for data alignment:

- Find It emoji packs partition the emoji pool.
- Localized emoji-name arrays match emoji count.
- Music Box songs have translation keys, notes, lyrics, valid drum timings, and known pitches.
- Translation dictionaries share the same keys as English.
- Initial models decode through their Effect schemas.
- Invalid nested messages are rejected by schemas.

These tests catch mistakes that ordinary example-based gameplay tests might miss.

## Persistence Tests

`src/main.test.ts` makes persistence a first-class contract:

- `PERSISTED_SETTINGS_MESSAGE_TAGS` must match the tested settings-message list.
- Every settings message emits `PersistSettings`.
- Transient gameplay messages do not persist.
- Import/export handles valid payloads, invalid payloads, and version mismatch.
- Legacy or malformed persisted data falls back safely.

This is important because root settings span all games.

## Design Pattern

The strongest pattern in the suite is:

1. Keep rules in pure update/domain functions.
2. Return named commands for side effects.
3. In tests, resolve commands explicitly by name and expected message.
4. Use Scene tests only where DOM wiring matters.
5. Use invariant tests for cross-file data contracts.

That mirrors the Foldkit architecture and keeps the tests close to how the app is built.
